# 📞 بی‌شماره — تماس بدون سیم‌کارت

یک برنامه‌ی کامل و **واقعاً قابل استفاده** برای تماس صوتی و تصویری بدون سیم‌کارت، بدون شماره تلفن و بدون ثبت‌نام.
صدا و تصویر با **WebRTC** مستقیم بین دو دستگاه رد و بدل می‌شود (رمزنگاری‌شده با DTLS-SRTP)؛ سرور فقط نقش «معرفی» دو طرف را دارد،
پس هزینه‌ی پهنای باند سرور عملاً صفر است و کیفیت تماس به اینترنت خودِ دو طرف بستگی دارد.

> بدون سیم‌کارت، بدون اپ‌استور، بدون شماره — فقط یک مرورگر. روی اندروید/آیفون هم با «افزودن به صفحه‌ی اصلی» مثل یک اپ نصب می‌شود (PWA).

---

## ✨ چه چیزی دارد؟

| قابلیت | توضیح |
| --- | --- |
| **تماس با لینک** | یک لینک بساز، برای طرف مقابل بفرست (واتساپ/تلگرام/پیامک). به‌محض باز کردن لینک، تماس وصل می‌شود. |
| **تماس با شماره‌ی ۶ رقمی** | هر آنلاین یک شماره‌ی موقت می‌گیرد؛ با شماره‌گیر روی صفحه، مثل گوشی واقعی زنگ می‌زنی. |
| **تماس تصویری** | روشن/خاموش کردن دوربین در میانه‌ی تماس، بدون قطع شدن صدا، و چرخش دوربین جلو/عقب. |
| **زنگ واقعی** | زنگ ورودی با Web Audio ساخته می‌شود + لرزش گوشی + تغییر عنوان تب. |
| **صامت / بی‌صدا** | قطع و وصل میکروفون در یک لحظه (بدون مذاکره‌ی مجدد WebRTC). |
| **جزئیات فنی تماس** | بیت‌ریت، تأخیر (RTT)، افت بسته، لرزش، کدک و اینکه مسیر «مستقیم» است یا از «رله (TURN)» می‌گذرد. |
| **متر صدا** | موج‌نمای زنده بر اساس صدای واقعی طرف مقابل (نه انیمیشن الکی). |
| **لیست آنلاین‌ها و تماس‌های اخیر** | با یک ضربه به هر کسی که آنلاین است زنگ می‌زنی. |
| **انتقال پشتیبان** | اگر شبکه‌ای WebSocket را ببندد، خودکار روی SSE + HTTP سوییچ می‌کند و تماس همچنان کار می‌کند. |
| **کد دسترسی اختیاری** | با `CALL_CODE` سرور را خصوصی کن؛ فقط کسانی که کد را دارند وارد می‌شوند. |
| **شماره‌ی ثابت دستگاه** | شماره‌ات روی آن دستگاه ذخیره می‌شود تا دوستانت همیشه با همان شماره پیدایت کنند. |

## 🚀 اجرا در ۳۰ ثانیه

```bash
cd call
npm install
npm start          # → http://localhost:8080
```

سپس در مرورگر باز کن: **http://localhost:8080**

> ⚠️ میکروفون فقط در **HTTPS** (یا `localhost`) اجازه می‌گیرد. برای استفاده‌ی واقعی بین دو نفر، برنامه را روی یک دامنه با HTTPS بگذار (پایین توضیح داده شده).

### تست سریع روی همان کامپیوتر (بدون سرور و دامنه)

1. صفحه را باز کن، تب **«لینک تماس»** → **«ساخت لینک تماس»**.
2. لینک را کپی کن و در یک تب دیگر (یا پنجره‌ی ناشناس) باز کن → **«پیوستن»**.
3. حالا یک تماس واقعی بین دو تب داری (میکروفون/دوربین همان دستگاه).

برای تست بین **لپ‌تاپ و گوشی**، فقط کافی است برنامه روی یک آدرس HTTPS عمومی باشد:

```bash
# نمونه: تونل موقت بدون دامنه
npx localtunnel --port 8080      # یا:  cloudflared tunnel --url http://localhost:8080
```

آدرسی که می‌دهد را در گوشی باز کن؛ لینک تماسی که می‌سازی خودش همان دامنه‌ی HTTPS را می‌گیرد و کار می‌کند.

## 🔁 چرا TURN لازم می‌شود؟

اکثر تماس‌ها با STUN مستقیم وصل می‌شوند. اما اگر هر دو طرف پشت **NAT سخت** باشند
(بعضی شبکه‌های اداری، اینترنت همراهِ برخی اپراتورها، یا حالت CGNAT)، مسیر مستقیم بسته است و
برای عبور از آن به یک سرور **رله (TURN)** نیاز است. بدون TURN، در آن حالت‌ها تماس در مرحله‌ی «در حال اتصال» می‌ماند.

راه‌اندازی TURN با coturn (کنار همین برنامه):

```bash
# روی سروری با IP عمومی
docker compose -f docker-compose.turn.yml up -d
```

بعد متغیرها را به برنامه بده:

```bash
TURN_URL="turn:YOUR_PUBLIC_IP:3478?transport=udp,turn:YOUR_PUBLIC_IP:3478?transport=tcp" \
TURN_USER="bishomare" TURN_PASS="یک-رمز-قوی" node server.js
```

پورت‌های لازم: `3478/udp`، `3478/tcp` و بازه‌ی `49160-49200/udp`.
برای شبکه‌های خیلی سخت (فایروال شرکت‌ها) بهتر است TURN روی `443/tcp` با TLS (`turns:`) هم بالا باشد.

> در پنل **«جزئیات»** داخل تماس می‌بینی که مسیر مستقیم است یا از رله می‌گذرد — یعنی همیشه می‌دانی چرا کیفیت این‌طور است.

## 🧠 چطور کار می‌کند؟

```
مرورگر A                    سرور سیگنالینگ (Node)                  مرورگر B
   │  hello ─────────────────────▶ │                                  │
   │  دعوت/زنگ ──────────────────▶ │ ─────────── incoming ──────────▶ │
   │  ◀──────────────────────────── │ ◀──────────── accept ─────────── │
   │  offer (SDP) ───────────────▶ │ ───────────── offer ───────────▶ │
   │  ◀───────────────────── answer │ ◀────────── answer ───────────── │
   │  ICE candidates ⇄ (تبادل از طریق سرور) ⇄ ICE candidates            │
   │                                                                    │
   └────────── صدا/تصویر رمزنگاری‌شده، مستقیم بین دو مرورگر ───────────┘
                        (سرور هیچ بسته‌ای از تماس را نمی‌بیند)
```

- **سیگنالینگ:** WebSocket روی `/ws`؛ اگر شبکه اجازه نداد، خودکار `GET /api/events` (SSE) + `POST /api/send`.
- **رسانه:** `RTCPeerConnection` با دو ترنسکیور ثابت (صدا و تصویر). خاموش/روشن کردن میکروفون و دوربین با
  `replaceTrack` انجام می‌شود، بنابراین **تماس قطع نمی‌شود و مذاکره‌ی مجدد لازم نیست**.
- **اتاق‌ها:** هر تماس یک اتاق دو‌نفره است؛ نفر دومی که وارد لینک می‌شود «پیشنهاددهنده» است. این قاعده از برخورد
  هم‌زمان دو پیشنهاد (glare) جلوگیری می‌کند.
- **حالت اتصال:** اگر `connectionState` خراب شد، `restartIce()` خودکار انجام می‌شود.
- **حریم خصوصی:** هیچ ثبت‌نام، شماره یا لاگ تماسی روی سرور نیست. فقط نام نمایشی و شماره‌ی موقت در حافظه‌ی سرور
  نگه داشته می‌شود و با قطع اتصال پاک می‌شود.

## ⚠️ محدودیت‌های واقعی (صادقانه)

1. **باید صفحه باز باشد.** چون سرور push ندارد، وقتی تب/اپ کاملاً بسته است گوشی زنگ نمی‌خورد؛
   زنگ فقط وقتی می‌رسد که برنامه در پس‌زمینه‌ی مرورگر باز باشد. (برای زنگ در حالت بسته باید
   Web Push + سرویس‌ورکر اضافه شود — قدم بعدی طبیعی این پروژه است.)
2. **آیفون:** زنگ و لرزش تا اولین لمس صفحه ممکن است بی‌صدا باشد (محدودیت iOS برای AudioContext).
   تماس بعد از زدن «پاسخ» کاملاً درست کار می‌کند.
3. **بدون TURN** بعضی شبکه‌های سخت وصل نمی‌شوند (بالا توضیح داده شد).
4. **تماس یک‌به‌یک** است؛ تماس گروهی و کنفرانس در این نسخه نیست.
5. اگر صفحه داخل **iframe** باز شود، مرورگر ممکن است میکروفون را ندهد — بنر بالای صفحه این حالت را تشخیص
   می‌دهد و با یک ضربه در تب جدا باز می‌کند.
